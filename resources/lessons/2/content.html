In Aether, you declare a variable with let.
The compiler performs Hindley-Milner inference, deducing the most general type that is consistent with how the value is used throughout the program.

let name = "Ada" -- inferred: String let count = 42 -- inferred: Int let ratio = 3.14 -- inferred: Float let active = true -- inferred: Bool

All bindings in Aether are immutable by default. Once a value is bound to a name, that binding cannot be reassigned. This design choice eliminates an entire class of bugs caused by unintended mutation — a root cause of many real-world failures in concurrent systems.

Shadowing

Because bindings are immutable, Aether permits shadowing — re-binding the same name in an inner scope. The outer binding is untouched; inside the new scope, the name refers to the new value. Shadowing is particularly handy after transformations:

let input = readLine() -- String let input = input.trim() -- still String, but trimmed let input = input.toLower() -- normalised
◆ Shadowing is not the same as mutation. Each let creates a fresh, independent binding. The previous value remains accessible to anything that already holds a reference to it — this keeps Aether's concurrency guarantees intact.
